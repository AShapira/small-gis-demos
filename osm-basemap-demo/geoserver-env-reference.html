Kartoza GeoServer 3.0.1 — environment variables

This reference targets the actual Linux AMD64 kartoza/geoserver:3.0.1 image used by this demo, inspected on 10 October 2026. It covers every external runtime input found in the Kartoza startup scripts/templates, the additional environment properties listed in the GeoServer 3.0.1 core reference, secret-file forms, and common misleading names from the example Compose configuration.

Defaults below are the image/script defaults, not the values in the running demo. “Core default” means the release property index does not specify a value; it is deliberately not guessed.

The image scripts were read directly. All startup library files except utils.sh also matched pinned Kartoza source 50b1796070ff41ac529fcf3b88ab1c28a21db4db byte for byte. For utils.sh, the installed image is the evidence. Native property names are checked against the GeoServer 3.0.1 property index. This is a configuration/source audit, not a claim that optional HTTPS, clustering, S3, database or telemetry deployments were exercised.

How to apply: put runtime variables under services.geoserver.environment in Compose, normally quoting boolean-looking values as strings. Editing .env alone has no effect unless Compose references the variable or passes that file as env_file. Recreate the container after changes. The demo.py start local development command constructs its own container arguments, so changes made only to compose.yaml do not automatically alter that path.

Precedence: GeoServer reads Java system properties before servlet context parameters before environment variables. Kartoza maps many convenient names to Java properties; use those names to avoid a lower-priority native environment value being shadowed. Dotted, mixed-case names are exact: in Compose use a quoted mapping key or supply them as -Dname=value through ADDITIONAL_JAVA_STARTUP_OPTIONS.

Scope: standard Linux variables and arbitrary plugin/library settings are not a finite Kartoza API. Java, GDAL, Tomcat and the optional OpenTelemetry agent have their own additional settings. In particular, MBSTYLE_ROOT_TILE_PIXELS is used here as a Java property, not as an independent container environment switch. The OpenTelemetry Java configuration reference covers the agent's full OTEL_* family.

Important behavior in this exact image
  • Initialization versus updates: existing gwc-gs.xml, quota XML, controlflow.properties and some Tomcat files are preserved by their generators. Changing the associated environment variable may not rewrite them. Update the persisted configuration through the appropriate API or file workflow. Our prepared catalog already supplies its own gridsets, gutter and quota configuration.
  • Credentials: .security.lock controls first initialization. The image does not unconditionally rotate credentials on every restart. RESET_ADMIN_CREDENTIALS is currently unused. Preserve /settings when depending on its locks, and use GeoServer's security API/UI for an existing account when appropriate.
  • Offline extensions: FORCE_DOWNLOAD_*=false avoids forced replacement, but missing ZIP archives still trigger network downloads. The exported demo was validated with outbound access blocked.
  • Default stable extensions: control-flow-plugin, csw-iso-plugin, csw-plugin, gdal-plugin, inspire-plugin, libjpeg-turbo-plugin, monitor-plugin, pyramid-plugin, vectortiles-plugin and wps-plugin. Our ACTIVE_EXTENSIONS=mbstyle-plugin overrides that list; merely writing controlflow.properties or monitor.properties does not activate those modules.
  • S3 configuration: all four S3 variables must be populated, and ADDITIONAL_JAVA_STARTUP_OPTIONS must contain -Ds3.properties.location pointing to the generated file, before the helper writes s3.properties. The compatible S3 extension must also be installed.
  • Internal HTTPS caveats: startup removes existing privkey.pem/fullchain.pem in CERT_DIR, has reversed JKS key/store password mappings in the connector transform, and fails to pass several declared HTTPS parameters to XSLT. Do not assume the old mounting instructions work unchanged. A reviewed custom /settings/server.xml or TLS termination at the GCP/private-network proxy avoids relying on this untested automatic path.
  • Logging: LOGGING_STDOUT=false does not switch off every console logger. GeoServer logging.xml is still generated with stdout enabled. Monitor auditing requires monitor-plugin, which our minimal demo does not activate.
  • No env knob for label language, POI collision spacing, gutter or tile metatiling: these are style/catalog/GWC configuration in this demo. No runtime settings or credentials were changed while producing this reference.
Current demo settings relevant to daily use

Stable activation: STABLE_EXTENSIONS=mbstyle-plugin, ACTIVE_EXTENSIONS=mbstyle-plugin; community activation: COMMUNITY_EXTENSIONS=mbtiles-store-plugin; both forced-download flags false. SAMPLE_DATA=false, RECREATE_DATADIR=false, INITIAL_MEMORY=1G, MAXIMUM_MEMORY=4G. GEOSERVER_DISABLE_STATIC_WEB_FILES=false, GEOSERVER_STATIC_WEB_FILES_SCRIPT=SELF support the bundled viewer. JAVA_TOOL_OPTIONS=-DMBSTYLE_ROOT_TILE_PIXELS=256 aligns MBStyle zoom levels. Credentials are intentionally omitted from this reference.
